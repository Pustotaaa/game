# Бездна — Voxel

Отдельная Windows x64 версия на **Godot 4.7.2+**: лесной лагерь и боевые этажи **2, 3, 4**. Этажи 5–10 закрыты. Браузерная игра в `../dist` остаётся самостоятельной 2D-версией.

## Запуск

Готовая сборка: GitHub → Actions → **Voxel Windows** → последний успешный запуск → артефакт **AbyssVoxel-Windows-x64**. Распаковать ZIP целиком, запустить `AbyssVoxel.exe`; `.pck` должен лежать рядом. Установка Godot для готового exe не нужна.

Для разработки открыть `godot/project.godot` в Godot 4.7.2 или новее и нажать F5. Используется GDScript и рендерер Compatibility / OpenGL 3.3. Нужны Windows x64 и видеодрайвер с OpenGL 3.3.

## Управление

- ПКМ или средняя кнопка + движение мыши: свободное вращение камеры, наклон ограничен, чтобы не уходить под землю.
- Колесо: зум. F11: полный экран. В меню есть сброс камеры.
- ЛКМ в лагере: путь к месту или входу в постройку. WASD / стрелки: движение относительно камеры. E: ближайший объект.
- В бою герой идёт сам; питомцы подходят к целям и атакуют. `1–4` — способности, пробел — способность первого питомца, `Q` — временный щит отряда. Кристаллы собираются кликом либо улучшением автосбора.
- Esc: пауза / закрыть окно. Меню и бестиарий останавливают бой.

## Что перенесено

Питомцы: кошка, волк и крылан, редкости, опыт, пассивные и активные способности; отряд до четырёх мест; дерево улучшений; яйца с исходными шансами; крафт и экипировка предметов; щиты, наступление бездны, 45-секундные забеги; стражи и боссы с подготовкой прерываемого удара; бестиарий. Здоровье сохраняется между последовательными этажами и восстанавливается в лагере.

Параметры исходной 2D-игры экспортированы в `assets/balance.json` скриптом `tools/sync_balance.cjs`. Дистанции и перемещение адаптированы под 3D; геометрия боевых арен и визуальные эффекты — новые. Баланс 3D-прохождения требует дальнейшего игрового тестирования.

Прогресс отдельный: `%APPDATA%/Godot/app_userdata/Бездна — Voxel/voxel-progress.json`, с резервной копией `.bak`. Сохранения браузера автоматически не импортируются. Сброс требует подтверждения. Тестовый режим использует другой файл и не перезаписывает прогресс игрока.

## MagicaVoxel

21 исходная модель в `assets/vox/`, формат **MagicaVoxel VOX 150**: герой, питомцы, враги и три босса, здания, дерево, ель, мост и реквизит. Их можно открыть и редактировать в MagicaVoxel. В этой среде GUI MagicaVoxel недоступен: модели созданы локальным кодом `tools/build_voxels.py`, а не вручную в редакторе. Это оригинальные ассеты, внешние наборы не использовались.

Один `.vox` = одна модель, размер до 256³, Z направлен вверх. Загрузчик поддерживает `SIZE`, `XYZI`, `RGBA`; многомодельные сценографы `nTRN`/`nGRP` надо свести в один объект перед сохранением. `scripts/vox.gd` строит индексированный меш только из открытых граней; один меш переиспользуется всеми экземплярами. Рельеф объединён в MultiMesh по материалам. Герой и питомцы анимируются перемещением целых воксельных моделей; скелетной анимации пока нет.

Для изменения модели: открыть `.vox` в MagicaVoxel, сохранить поверх, перезапустить игру. **Не запускать генератор после ручных правок**: он воспроизводит исходные модели и перезаписывает файлы. После редактирования обновить SHA-256 и размеры в `manifest.json`, затем выполнить проверку.

## Сборка и проверки

```sh
python3 godot/tests/validate_assets.py
node godot/tools/sync_balance.cjs
node --test tests/gameplay.test.cjs
godot --headless --editor --path godot --import --quit
godot --headless --path godot -- --smoke-test
bash godot/tools/build_windows.sh
```

Для экспорта установить официальные Windows-шаблоны **той же версии Godot**, что и редактор. `GODOT_BIN` позволяет указать путь к бинарнику. ZIP появляется в `godot/builds/`, папка исключена из Git. Workflow `.github/workflows/voxel-windows.yml` выполняет проверки и экспортирует Windows x64, не затрагивая GitHub Pages.

Проверка изображения при наличии дисплея:

```sh
mkdir -p /tmp/voxel-captures
godot --path godot -- --visual-test=/tmp/voxel-captures
```

Проверено на Linux в Godot 4.7.2: загрузка VOX, пути к пяти объектам, непроходимость реки и воронки, мышиное вращение и зум, панели, развитие и сохранение, запуск всех трёх арен и боссов, навыки и возврат в лагерь. Windows exe экспортирован; его нативный запуск на Windows в этой среде не проверялся.
